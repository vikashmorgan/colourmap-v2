QuestionWhat does .get() do, and why use it instead of [ ]?
Answer
Both read a value from a dictionary by its key. The difference is what happens when the key is missing. raw_book["title"] → the title, or a crash (KeyError) if there is no "title" key raw_book.get("title") → the title, or None if there is no "title" key raw_book.get("author_name", []) → the authors, or [] if there are none So .get() never crashes on a missing key: it gives back None, or the default you put after the comma. Why the program uses it: the books come from the internet and are not trusted yet. Some have no title, no page count, no authors. With [ ] the whole program would stop on the first incomplete book. With .get() it carries on, and clean() decides what to do: reject a book with no title (None), keep a book with no authors as [] so len() still works. It is used for the menu too: MENU_NUMBERS.get(choice, choice) turns "1" into "fetch", and gives back what you typed when it is not a number. Rule of thumb: [ ] when the key must be there (after clean(), every book has its five keys, so book["title"] is safe); .get() when it might be missing (raw data, user input).
QuestionWhat are an API and a URL?
Answer
A URL is an address on the internet, like a postal address for a page or for data. Yours, in parts: https:// how to talk to the website (secure web) openlibrary.org which website /search.json which service: search, answering in JSON ? "here come my options" q=mountains the search word fields=title,… only send me these fields limit=100 at most 100 books & separates one option from the next An API (Application Programming Interface) is a door a website opens for programs instead of people. In a browser, openlibrary.org gives you a page made for your eyes. Through the API, your program gets raw data in JSON, made for code to read. Like a restaurant: the waiter and the menu are the API. You do not go into the kitchen (their database); you send an order in the agreed format (the URL with its options) and the dish comes back (the JSON). In the program: r = requests.get(URL, timeout=30) send the order to the API's address data = r.json() the dish: JSON turned into Python return data["docs"] the list of books inside it For the oral: "An API is a website's interface for programs: I send a request to its URL, with options like q=mountains and limit=100, and it answers with data in JSON that my program can read."
QuestionWhat does "memory" mean, as in "fetch brings the books into memory"?
Answer
Memory is the computer's short-term memory (RAM): where a program keeps its variables while it is running. In this program, "in memory" means inside the variable book_list. Memory (book_list) File (backup.json) inside the running program on the hard drive gone when you quit the program stays after you quit filled by fetch() + clean(), or load() written by save() That is why there are three options: fetch: internet → memory (the books are in book_list, but only while the program runs) save: memory → file (now they survive after you quit) load: file → memory (back into book_list next time, no internet needed) And it is why the unsaved flag warns you at quit: the books in memory are not in the file yet; quit now and they are lost. For the oral: "Memory is where the program keeps book_list while it runs. It disappears when the program stops, so save() writes it to backup.json to keep it."
QuestionWhat is the difference between fetch and save?
Answer
They move the books in opposite directions. fetch() goes to the internet: it asks Open Library for the books with requests.get(URL) and gives back the raw list (raw_book_list). clean() turns it into book_list, the clean books. At that moment the books live only in the program's memory: close the program and they are gone. save() goes to your disk: it writes book_list, the books in memory, into the file backup.json (json.dump). Nothing comes from the internet; the books simply become a file that stays after the program ends. load() is the way back: it reads backup.json into memory, so the program works with the internet off. In one line each: fetch: internet → memory save: memory → file load: file → memory That is why the menu asks you to fetch first: save has nothing to write until book_list holds books.
QuestionWhy do we not use pip (pip.get or similar) to get the files into Python?
Answer
Because pip and the program do two different jobs, at two different moments. pip is a tool you run once, in the terminal, before the program: pip install requests. It downloads a library (here requests, someone else's code) onto your computer so that import requests works. pip never brings data, and the program never calls pip. There is no pip.get. The get you are thinking of is requests.get(URL), inside fetch(). That is the library pip installed, now at work while the program runs: it asks the website for the data. Files on your own computer need neither: Python reads them itself with open() and json.load() (that is load()). So: pip install requests → once, installs the tool (session 7) requests.get(URL) → every fetch, gets the data open() + json.load() → reads a file already on disk requirements.txt, which you hand in, simply lists requests so the teacher can run pip install -r requirements.txt and get the same tool.
The missionWhat the teacher asked for

Write a Python program that runs in the terminal. It downloads data from a public web API, cleans it, saves a copy to a file, and lets the user search, summarise, sort and chart it from a menu. Everything is text: tables and bar charts are made of characters.

The menu: eight choices

1FetchDownload, clean, keep in memory. Say how many kept and rejected. No internet must not crash it.
2SaveWrite the clean records to a JSON file, indented. Say when an old backup is replaced.
3LoadRead the backup back. Works offline. Say so if there is no file.
4SearchEvery title containing a word, capitals ignored. Nothing found is normal.
5SummaryA lined-up table with a total and an average. Missing shows as —, never None.
6ChartCount per category, # bars, biggest first, longest about 30. Top 15, say how many left out.
7SortPick a field, print sorted, reusing option 5's row. Missing values last.
0QuitIf the data is not saved, ask first.

The rules for the whole program

  • Bad input never crashes it: a letter, an empty line, a wrong number, Ctrl-C.
  • Clean once, in one function, clean(). A year is an int or None, never "2012".
  • Reject rows with no title, rows that are not dicts, and duplicates.
  • Open every file with with.
  • Catch named exceptions, never a bare except:.
  • One function, one job.
  • Standard Python plus requests. No plotting libraries.

The API we use

Open Library, the easiest one: books about mountains, with title, authors, year, pages and subjects. No key, no payment.
